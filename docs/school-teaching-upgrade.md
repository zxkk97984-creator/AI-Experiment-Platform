# 单校教学功能升级与上线操作

本轮按一所学校、100–200名在线学生的业务设计实施。迁移版本为 `20261003_0001`，验证记录于2026-10-08更新。这里说明管理员和教师的实际操作、存量兼容与部署步骤。功能测试和本机联调不替代学校目标服务器的容量、TLS及恢复验收。

## 功能和操作入口

| 业务 | 入口与规则 |
|---|---|
| 授课安排 | 管理员进入「授课安排」，明确课程、学期、教学班、教师；教师进入「班级授课」。课程内容负责人只维护共享内容，不自动拥有其他班学生数据权限。 |
| 名单和转班 | 管理员可补充实例名单、同课程同学期转班；原因必填。原提交和原成绩保持原归属，成绩转入为另一个明确操作。归档班级与闭学期只读。 |
| 班级任务 | 作业/考试创建时选择本班实例，或在授课页面复制共享模板为独立草稿；各班分别编辑时间和规则。教师无法自行设置授课班级或访问其他班提交。 |
| 账号交付 | Excel预检、确认、异步执行沿用原流程，学号保留前导零。新建和管理员重置签发独立16位随机密码，默认7天有效，首次登录强制改密。管理员再次验证本人密码后，在签发起24小时内导出凭据。 |
| 课程资料 | 三端独立菜单，课程公共区和章节区；内容负责人上传/排序/替换/发布/归档，授课教师阅读共享资料并关联本班活动。学生只看已发布资料和本班活动。 |
| 逐Cell反馈 | 教师按稳定Cell ID配置数值区间、近似、输出、形状或私有Python检查；运行后异步显示反馈，源码修订后旧反馈过期。正式提交在干净环境重放冻结版本。 |
| 实验成绩 | Cell、指标、效率合计100分；效率默认0，启用后指定基准节点三次程序执行取中位数。默认5次正式提交取最高，可配置最后一次。 |
| 排行榜 | 仅同班、同评分版本的有效已发布成绩；同分同名次，默认匿名。教师可切换实名，排行榜不参与成绩计算。 |
| 成绩簿 | 三端「课程成绩簿」。教师可配置两级比例、绑定本班正式来源或人工录分、确认缺交/免修、调分、预览、发布、归档、XLSX/CSV导出；学生只查看本人官方版本。 |

管理员选择课程、教学班、教师和补充学生时使用分页选择窗口，每页20条；学生可跨页多选，确认后才写入表单，取消保留原选择。教师按完整姓名或账号精确搜索，学生按姓名、学号或账号搜索。学期会完整加载全部页；更换学期会清空原教学班，更换授课实例会清空待添加学生。已在本班的学生不能重复添加，归档班级和关闭学期不能用于新建授课。某类候选加载失败可单独重试，不影响其他选择。

管理员在课程资料中点击章节作业或考试，会直接进入该任务的编辑页；「返回课程资料」恢复原课程和授课班级，刷新编辑页后仍然有效。管理员从其他入口打开任务编辑页时返回授课安排；教师保留原列表返回入口。显式指定的课程不在列表首100条时按ID补取，不会自动换成第一门课程。

共享模板与本班评分配置均支持在Cell的「自定义Python」规则中上传`.py`。文件须为UTF-8、Python语法有效且不超过20,000字节。上传只校验并填入当前草稿，不执行脚本、不自动保存或发布；填写后仍需保存、试评并发布。上传失败保留原脚本；切换班级、实验或删除评分点后，旧请求不会覆盖新配置。本班入口仅允许管理员及当前授课教师使用，关闭学期或归档授课后不可上传。

班级脚本接口为`POST /api/v1/offerings/{offering_id}/experiments/{kind}/{entry_id}/assessment/check-script`，`kind`为`lesson`或`module`；请求使用multipart字段`file`，响应为`{"script":"…"}`。共享模板接口和权限保持兼容，本班上传不会修改共享标准或其他班级的配置。

随机密码只在独立加密交付表保存。普通批次报告、审计和日志没有密码；改密、再次重置、导出窗口到期及账号停用会清除交付密文。加密密钥必须由运维单独保护，不能用JWT密钥替代。详见[账号管理](account-management.md)。

资料普通文件默认100 MiB，视频与ZIP默认500 MiB；前端读取API返回的配置上限。Nginx资料入口默认512 MiB，预留multipart开销。改变业务上限时必须同步调整API配置、Nginx和学校外层代理；不能只改`.env`。PDF和视频可预览，其他文件下载，官网链接由浏览器跳转，服务端不访问外链。下载每次重新核验账号、实例、发布状态、资料和会话版本；签名地址没有脱离授权的永久访问权。

上传执行扩展名、大小、格式结构检查，ZIP不在服务端解压或执行。它们是格式与访问保护，不等于杀毒扫描；若学校要求AV/CDR，应在私有存储流程接入并验收。设计依据：[OWASP文件上传规范](https://cheatsheetseries.owasp.org/cheatsheets/File_Upload_Cheat_Sheet.html)。

实验规则、隐藏脚本和参考答案不进入学生资源或私有评测日志。基础设施失败保留证据，进入重试或复核，不能按学生错误扣分。人工改分保存原自动分、原因和修订；晚到任务不得覆盖人工分、归档分或撤权后的官方分。整班切换评测版本先冻结全部历史正式提交，核对完成才统一切换；期间阻止新正式提交，练习反馈仍可使用原版本。

成绩先归一到百分制，再用Decimal做两级加权，展示两位小数。默认模板为平时30%、实验40%、考核30%，教师确认前可编辑。待评分阻止发布，缺交必须明确确认；免修仅在同栏目重分配，整栏免修须调整方案。发布时核对修订号与预览摘要；名单或来源分变化则409，需重新审核。官方版本冻结名单、权重、来源分和修订，后续更改形成新版本。详见[成绩簿](gradebook.md)。

## 存量升级和归属核对

1. 先备份数据库、私有文件对象、环境镜像和独立加密密钥。确认原`alembic_version`与备份校验和，恢复演练使用隔离库和隔离存储。
2. 先在部署方的新运行环境安装当前`backend/requirements.txt`，再按仓库统一入口升级。JWT依赖已从python-jose切换为PyJWT；本轮保留原开发虚拟环境，旧环境须更新依赖后才能启动新版API。空库仍须经过basic环境种子阶段；生产必须提供真实审核过的环境镜像digest。已有basic环境的存量库不会替换已有版本。

   ```bash
   # 使用已安装当前依赖的运行环境及部署方配置的环境变量。
   # 不要在命令或源码中填写生产密码。
   backend/.venv/bin/python scripts/bootstrap_database.py
   ```

3. 旧课程绑定只生成`pending_assignment`候选，不给教师自动授权。管理员逐项核对教师、课程、学期和班级，再「确认并激活」。如果名单跨班冲突，先核对转班，不绕过同课程同学期唯一成绩归属约束。
4. 在管理员授课页面「历史归属核对」填写原因，确认未归属实验记录。只能确认课程一致且学生有实例名单的记录；正在运行或重评、重复记录和归档实例拒绝修改。历史分数、提交ID与评测版本保持不变。
5. 历史作业/考试只有全部参与者明确属于同一班，才允许整项确认。混班来源继续由学生本人和管理员查看历史；不能整体猜测归属。教师核对这些个人成绩时可在本班成绩簿人工录分，并在原因中记录原来源和审核依据。
6. 转班默认只移动有效名单。管理员可另行「明确转入历史实验成绩」，要求同课程同学期、模板/评测版本一致、目标没有同入口记录且双方不在重评或运行中。只转实验记录归属，原提交分与官方成绩档案保留。不同版本应人工核对录分，不自动换标准重算。

**禁止生产数据库降级该迁移。** 有业务数据的回退通过已校验备份恢复；`DAI_ALLOW_TEACHING_DOWNGRADE=1`只供明确的disposable测试库使用，生产即使设置该变量也会拒绝DDL。

## 部署和试点顺序

- 使用已审核的不可变镜像，API、Judge、Lab Worker、环境构建与存储对账等组件按`docker-compose.prod.yml`部署。Lab Worker读取数据库持久队列；Redis唤醒丢失仍可轮询恢复。
- 配置学校域名、TLS、代理可信CIDR、Cookie安全项、账号加密密钥。统一身份平台未提供前保留学号登录，不显示未接通的扫码/手机登录。
- 将`material_data`及所有studio/video/cover/lab对象、数据库成绩版本纳入一致备份和恢复。保留旧环境与仍被成绩/提交引用的文件对象，先对账再按生命周期清理。详见[备份恢复](backup-restore.md)。
- 在线学生数量与同时运行容器数量分别配置；200人在线不表示200个训练容器并行。配置CPU/内存/磁盘预算、交互内存保留、Kernel上限、训练并发与队列租约；先做阶梯准入、失败恢复和磁盘阈值验证。
- 效率计分需独立基准Docker节点，`DAI_LAB_BENCHMARK_NODE_ID`取自该节点的`docker info --format '{{.ID}}'`。普通API/worker使用`DAI_LAB_WORKER_MODE=general`；专用worker使用`benchmark`，其`DAI_LAB_WORKER_NODE_ID`必须与该真实daemon ID相同。未配置或身份不符会拒绝效率评分准入，普通worker不会领取效率任务；同daemon即使误配general也不能运行交互Kernel。共享数据库、私有存储和该节点镜像/挂载路径由运维核对，物理独立、CPU稳定及三次基准测量仍须目标节点验收；不要在共用课堂执行节点上设置benchmark模式。
- 使用[容量脚本说明](school-capacity.md)在专用验收班执行200独立用户、30分钟混合负载。普通读取p95目标≤1秒、正式提交确认≤2秒；入队耗时与实际执行耗时分别记录，不能把只读smoke当成混合容量结果。
- 完成[生产证据清单](production-evidence-checklist.md)后安排一个试点班：管理员核对授权、教师试评并确认标准、学生登录改密/下载/提交/查看成绩；再扩展到全校。AI仍按学校既有治理审批开关控制。

## 验证与证据

本轮只使用合成身份、独立测试数据库及专用容器；未迁移现有业务库，也未发布到学校生产服务器。

真实浏览器→API→MySQL→Docker联调已完成：学生看到已发布资料、逐Cell检查通过、正式提交在干净环境重放得100分；教师仅看到自己的班，配置默认两级比例、录分、发布、归档和下载Excel；学生仅看到本人结果。第二个版本绑定该正式实验分，按`80×30% + 100×40% + 80×30%`得到88.00；此前归档保持80.00。

运行证据位于忽略目录`.runtime/school-verification/`，不随源码发布。
